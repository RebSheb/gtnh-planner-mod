## 1. Solver

### 1.1 The model

The balancer is a chain of LPs on ojAlgo 57.4.0. [`ModelData`][md] builds the chart once per solve. [`ModelBuilder`][mb] turns it into variables and rows:

- one extent per machine in crafts/s ([`extents`][mb-ext]). A pinned machine gets lower = upper = its pin.
- one flow ≥ 0 per wire ([`flows`][mb-flows]).
- one external ≥ 0 per connected port ([`externals`][mb-externals]). That is what enters or leaves the plan at that port.
- one conservation row per connected port ([`conservation`][mb-cons]): Σ flows + external − qty·extent = 0, scaled by 1/max(1, qty).
- pool rows for shared machines ([`pools`][mb-pools]), drawer rows and port rate rows.

Ports joined by wires form a network. [`buildGates`][md-gates] finds them with union-find and gives each network two gates: one for imports and one for surplus. AUTO has no integer variables. A gate is closed by setting its ports' externals to an upper bound of 0 ([`Solver.closeGatesOutside`][s-close]). Which gates stay open is the whole problem. Recipe ratios almost never close exactly so most plans need some.

Every model comes from one ojAlgo environment with its presolvers cleared ([`ModelBuilder:44`][mb-env], [`:80`][mb-envf]). Options: `time_abort` = `time_suffice` = 30 s, feasibility `NumberContext.of(12, 10)`, one thread per model.

### 1.2 What was broken in alpha 5

**Wall clock changed the answer.** The whole solve had 20 s ([old `Numerics:24`][o-num-solve]). Each stage had up to 15 s ([`:44`][o-num-stage]) through a per-model limit that took whatever was left of the budget ([old `ModelBuilder:59-63`][o-mb-limit]). The alternatives had 750 ms ([`:47`][o-num-alt]). The gate MILP reported "optimal" only if it finished inside its own time limit ([old `Solver:152-165`][o-s-milp]). A loaded CPU produced a different answer. A stored leftover split whose place wasn't found that time was spread over the places that were.

**Alternatives never reached a real plan.** The enumerator added one "current" row per open gate before evaluating anything ([old `Enumerator:64-69`][o-en-rows]). It stopped once the list held 8 ([`:136`][o-en-cap]). With 8 or more open gates no real alternative was ever evaluated. The swap LPs still ran first, up to 1,024 of them ([`:106`][o-en-swaps]). Every plan in our corpus past toy size had 8 or more.

**One plan, one model.** Unwired parts were solved together. One part that couldn't balance failed the whole plan and AUTO showed no counts anywhere ([old `Balancer:214-221`][o-bal-fail]). Gate support measured "zero" against the largest gate flow in the plan ([old `SolveContext.gateSupport`][o-gs]) so a small line next to a big one could lose its gates. The every-machine-runs floors came from the smallest machine anywhere ([`machineRunFloors`][o-floors]). Pin conflicts were named plan-wide ([`diagnosePins`][o-pins]). Work grew with the square of the plan. Ten tiled platlines cost 68 times one.

**Presolve was wrong for these models.** ojAlgo's presolve declared balanceable gate sets infeasible (230_platline's second pass). It ran in exact `BigDecimal` and was 85% of a solve. The big-M gate MILP claimed 2 gates optimal where 1 balanced. On another run it said nothing balanced.

**Ties were path dependent.** The deletion filter read whichever optimal vertex the simplex returned. Turning presolve off changed 230_platline's answer. `canonicalize` silently returned the uncanonical point when its own LP failed ([old `Solver:295`][o-canon]).

**The floor sat in the noise.** With no unpinned machine running the floor was 1e-7 crafts/s. On a plan moving thousands a second that is below simplex tolerance.

**Edits waited on dead work.** `SolveService` never cancelled a running solve. An edit during a 30 s solve waited for it and then threw it away. The snapshot matched ports to resources by testing every port against every resource found so far ([old `SolveInput:282-289`][o-si]) on the client thread.

### 1.3 What we did

Eight steps. Each one had to reproduce the goldens from step 1 or explain the difference.

**1. Harness ([00e0500](https://github.com/jackwrichards/gtnh-planner-mod/commit/00e0500baf260b582093c70d79cc0ecf4a0130aa)).** A corpus of real plans exported from the game with `call solvedump` (14 in [`solver-corpus/`][corpus] plus 16 gtnh-flow charts). A golden of each plan's whole answer ([`SolverGoldenTest`][t-golden]). A timeless mode so no clock touches a test. `SolverBench` and `SolverCensus` for timing and model counts.

**2. Parallel evaluation (same commit).** Independent LPs run on the solver's own `ForkJoinPool` ([`Parallel`][par]). Threads = max(1, min(16, cores − 2)). [`Parallel.map`][par-map] writes `out[i]` and joins so results come back in item order. Output is identical on any thread count. 4–5x on plans with many leftovers. Platline went from 0.99 s to 0.25 s.

**3. Exact gate count ([8571f64](https://github.com/jackwrichards/gtnh-planner-mod/commit/8571f646e482d33714d3f3deb4636f1b0cab29bd)).** The big-M MILPs were replaced with `GateSearch`. Needed gates first. A reweighted-L1 start. A canonical deletion filter for a minimal set. Then cores and a least hitting set to prove it minimum. Every step was an LP feasibility query. Step 8 later deleted all of this. What it left behind is still here:

- Presolve off for every model.
- Every AUTO model runs through [`Solver.run`][s-run]. It tries two simplex set-ups in turn ([`OPINIONS`][s-op]: one with 5 equilibration passes, then ojAlgo's default). A point is accepted only if [`SolveContext.validate`][sc-val] passes. That checks each port's residual against max(1, qty, |extent·qty|) at 1e-6. A model counts as infeasible only when neither set-up gives a conserving point.
- Ties break on fixed weights. [`tieWeight`][s-tie] is a SplitMix64 scramble of the index mapped to [1, 2). No two sets of ports weigh the same.
- [`SolverPathTest`][t-path] adds every model's variables in reverse and solves again. The answer must be bit-identical.

Answers that moved: 230_platline went from 2 gates to 1. Full platline went from 45 to 44 and mv from 31 to 30.

**4. Alternatives per leftover ([d403761](https://github.com/jackwrichards/gtnh-planner-mod/commit/d403761e9e62643c8852d3f8008c16399decac82)).** [`Enumerator.enumerate`][en] treats each open gate as a decision. One LP per decision checks whether that leftover can go anywhere else at all. Movable decisions then swap with every closed gate (capped at 1,024) and each decision keeps its best 8. Swaps are counted, never timed. A plan where every leftover has one possible place now says so in 18 ms instead of running 1,024 swaps.

**5. Islands ([04e6dc9](https://github.com/jackwrichards/gtnh-planner-mod/commit/04e6dc942302def76cfecde37475895d0d014e42)).** [`Islands.of`][isl] is union-find over machines joined by wires, by a shared machine's pool and by a drawer's links. Only shared machines with a cap are snapshotted as pools ([`SolveInput:203`][si-pool]). [`Balancer.solveIslands`][bal-isl] solves each island alone through `Parallel.map` and merges extents, flows, externals and gate support back by id. One `commit` and one `SolutionView` come out. A broken island adds its note. The rest stays solved.

[`Balancer.Cache`][bal-cache] keys an island by `List.of(snapshot, solverEffort)`. `SolveInput` is a record so the key is by value. It keeps three maps: `last`, `before` and `current`. A finished solve rotates them. A stopped one keeps what it finished. Undo is a cache hit. [`SolverIslandTest`][t-island] checks that 4 tiled copies each of platline, the nitrobenzene power plant and hv-diesel match the plan alone to 1e-9, and that the cache never answers for an island that changed.

**6. No clocks ([103bd5c](https://github.com/jackwrichards/gtnh-planner-mod/commit/103bd5cc9aefb16ba25ddd52acf5d5864194a780)).** `Budget` is gone. Work is counted. Each model keeps the 30 s [`modelSafetyMillis`][num-safe] that no working model reaches. [`SolveService.submit`][ss-submit] bumps a sequence number. [`superseded`][ss-sup] is true once a newer request exists. [`SolveContext.checkStop`][sc-stop] throws [`Balancer.Stopped`][bal-stop] (no stack trace) before the next model. Snapshot matching now goes through an index ([`Ingredients.keysOf`][si-keys]): an item files under `(item, damage)` and each ore id, a fluid under its `Fluid`. [`resourceOf`][si-res] only tests ingredients filed under the port's own keys.

**7. ojAlgo 57.3.1 → 57.4.0 ([b22a623](https://github.com/jackwrichards/gtnh-planner-mod/commit/b22a623b123b95f73cbc3ab5b55f4a499f092cc6)).** Its sparse dual simplex. Identical answers on every golden plus the path and island tests. Ten platlines under one shared machine (one 490-machine island) went from 13.4 s to 1.4 s. Warm restarts through `IntermediateSolver.update` did not pay off. ojAlgo rebuilds after every infeasible result and most of the gate search's questions were infeasible on purpose.

**8. A new objective ([1e5f5df](https://github.com/jackwrichards/gtnh-planner-mod/commit/1e5f5df766feb54fbe44605e78ba4d64198a22a7)).** With the gate count exact we could see that fewest gates was the wrong thing to minimize. On gtnh-flow's palladium_line it gave 2,717 machines and 168,000/s traded. The old heuristic had 421 machines and 12.6/s. Least material and downstream-first rankings switched whole branches off and bought their parts. Forcing every machine on through few gates gave 8,305 machines.

AUTO is now lexicographic on machine steps ([`BalanceMode:43`][bm]: fast path, then trade, then flow):

- [`ModelData.steps`][md-steps] builds a graph of machines and networks. Each machine points to the networks it makes into. Each network points to the machines it feeds. [`Loops.of`][loops] collapses strongly connected components with an iterative Tarjan so a recycle loop counts as one step.
- An input port's steps = 1 + the fewest machines before any of its makers. An output port's steps = 1 + the most machines after any of its takers. In farm → mill → oven an input of wheat counts 1 and an input of flour 2. An output of wheat counts 2 and an output of flour 1.
- [`Solver.levels`][s-levels] keys each port by `((buying ? 0 : 1) << 32) − steps`. All buying levels come first with the most steps first. Then selling with the most steps ahead first.
- [`TradeStage.settle`][trade] runs one LP per level ([`leastAt`][s-least]) weighting only that level's externals. The result is held as a bound ([`tradeModel`][s-trade]) before the next level. A level that reached only rounding (≤ 1e-9 of the largest extent) is closed outright.
- [`FlowMinStage`][flowmin] then minimizes Σ flow with every level held ([`leastFlowHolding`][s-lfh]). Then [`canonicalHolding`][s-canon] picks one point among the ties with externals weighted 1e6 above flows.
- [`SolveContext.commit`][sc-commit] sets anything under 1e-11 of the plan's largest rate to exactly 0. Idle machines read 0 instead of x<0.001.
- [`SolutionView.unneeded`][sv-unneeded] lists unpinned machines the answer left at 0. The board adds them to [`Unanchored`][unanch] (parts with no pin anywhere) in [`BoardSession.unsetParts`][bs-unset] and asks for a count on all of them.
- `GateSearch`, `GateCountStage`, `ExternalMinStage` and the machine floors are deleted. No hardcoded small number decides an answer anymore.

[`TradeRuleTest`][t-trade] pins the rule with a bread chain (farm → mill → oven → cake). Short of wheat it buys wheat and runs the mill ([`:90`][t-trade-90]). It never buys flour. Spare wheat is milled and the flour sold at the oven ([`:100`][t-trade-100]). A cake maker on the flour line takes the spare ([`:110`][t-trade-110]). A cake maker nothing needs is reported as unneeded ([`:130`][t-trade-130]).

The choices panel explains each option by the same rules ([`Preference.rankOf`][pref]): buys more or further down the line, sells more or earlier in the line, moves more. [`Enumerator.evaluateSupport`][en-eval] settles a support exactly as AUTO does. [`Spares.apply`][spares] mixes the stored split from the alternatives' points. It validates the mix and keeps the solver's own point if the mix doesn't conserve.

**At 19,600 cards ([a8fc50e](https://github.com/jackwrichards/gtnh-planner-mod/commit/a8fc50e7949a51f8c4fa3558222e7c4f7f4502c1)).** Each choice rebuilt a plan-wide key. That was 87% of a 186 s solve. Choices now keep their island's key. The wiring notes find who makes an ingredient through an index instead of scanning the plan per import. The cache used to hold a fixed 256 islands and a 400-island plan thrashed it. Now it keeps exactly the last two solves.

## 2. Frame time

Commit [d3ca16e](https://github.com/jackwrichards/gtnh-planner-mod/commit/d3ca16ed1794c153a74808fd83524c4293826a5d). The test plan is Platline tiled 400 times: 19,600 cards with 9,800 machines placed in the world. Frame cap and vsync off.

| | alpha 5 | beta 1 |
| --- | --- | --- |
| Board at zoom 1, still or panning | 1.1 fps | 135–165 fps |
| Board fully zoomed out (~1,000 cards and drawers on screen) | ~3 fps | ~60 fps |
| Overlay in the world | 2.2 fps | 165–185 fps |
| First open in a session | 17 s frozen, 23 s until smooth | 5 s frozen, 11 s until smooth |
| Opening a 196-card plan | – | 0.2 s |

**ModularUI walked every card every frame.** [`BoardCanvas.getChildren`][bc-children] now returns [`inView()`][bc-inview]: cards and drawers whose box overlaps the view plus a 48 px margin, plus anything raised, carried or holding focus. [`candidates()`][bc-cand] files them in a hash grid of 512-unit cells. The grid is rebuilt only when the graph version, the models or a placement changes. Zoomed far enough out it takes every filed cell. Off-screen cards still pick up new models through [`onUpdate`][bc-update].

**NEI asked for a full board layout every frame.** NEI lays out every frame and our layout style passed that on. [`FlowchartLayoutStyle.layout`][fls] now schedules a resize only when the screen, NEI's item panel x or the window size changed ([`:84-95`][fls-84]).

**The overview rebuilt everything.** [`OverviewRail.index`][or-index] caches a per-resource [`Index`][or-Index] of drawers with a rule, rate-pinned unwired ports and open ports. It rebuilds only when the graph, its version, the models or the totals change. Rows outside the list are skipped but keep their height ([`:532`][or-skip]).

**Wires.** [`WireLayer.wires`][wl-wires] returns the cached list unless a route arrived, a drag is on or [`quickKey`][wl-quick] changed. Only then does it rehash the full geometry. Anything that moves cards outside an edit calls [`moved()`][wl-moved]. Hover hit tests ([`hit`][wl-hit]) and wire hops ([`hops`][wl-hops]) go through [`SegmentGrid`][sg] (64-unit cells). The still parts (shadows, casings, cores, arrows) are recorded once into a GL display list and replayed ([`draw`][wl-draw]). Only the hover halo is drawn fresh, in one [`Hyb.beginBatch`][hyb-batch]. Far out every wire keeps [`LEAST_PX = 1.5`][wl-least] screen pixels. The shadow drops below 0.8 px per board unit and arrows below 0.5. That is the flicker fix.

**Zoomed-out names.** [`ZoomedOutLabels.draw`][zol] places names only when zoom or a name's position changes. [`lay`][zol-lay] goes by priority (cards, then drawers by |rate|) against two grids of 64 px cells. All backings go out in one batch.

**Loading was O(n²).** Each wire and drawer was checked against all the others as it was added. [`Graph.addEdgesLoaded`][g-edges] and [`addDrawersLoaded`][g-drawers] build one map each and bump the version once. The doc comment notes thousands of wires used to take most of a minute.

**Regex per lookup.** The machine maths normalized names with regular expressions on every lookup. [`MachineTable.normalizeMachineName`][mt-norm] and its siblings in `RecipeRules` are memoized per name.

**Over the world.** [`WorldIndex`][wi] files placements in 16-block columns and is rebuilt only when the plan, the dimension, the snapshot, the known ghosts or a graph version change. The look ray and the overlay ask it instead of every placement. [`PlanSnapshot.cardOf`][ps-card] and [`wiresFrom`][ps-wires] are maps built once per snapshot. Multiblock ghosts are captured once per structure into GTNHLib vertex buffers ([`GhostMeshes.capture`][gm-cap]: `startCapturing` then `stopCapturingToVBO`, render passes 0 and 1). A ghost with any of its blocks built falls back to block-by-block drawing (checked every 500 ms). [`PlanOverlay.onRenderWorld`][po-render] keeps only placements inside a vanilla `Frustrum`. Display lists were not an option: block rendering recorded into one comes out invisible under Angelica.

**Tried and dropped.** Display lists for zoomed-out card faces (Angelica replays them no faster than drawing them). Rendering board tiles into textures (about 175 fps fully zoomed out but some 500 lines of framebuffer code for a case few plans reach).

**How it was measured.** [`DevStress`][stress] tiles the open plan, places it in the world and animates pan, zoom or yaw every frame. [`DevPerf`][perf] records frame times (p50, p95, p99, max) and per-part sections: `canvas`, `wires.route`, `wires.draw`, `cards`, `drawers`, `overview`, `session.tick`, `solve` and the overlay's `ar.*` ([`PlanOverlay.lap`][po-lap]). Both run from the dev harness (`call 'stress?copies=400'`, `call 'perf?start=1'`). Steps are in [performance-at-scale.md][d-perf].

## 3. Edit latency

Commit [58f9e3d](https://github.com/jackwrichards/gtnh-planner-mod/commit/58f9e3d552f1f46fc742c218943ea5f127cd2c34).

**The freeze after every edit was the save.** Every edit encoded every plan on the client thread. In a dev world with 21 plans that was 0.94 s encoding 5.7 MB and 0.36 s writing a 49 MB debug copy nothing read. 1.4 s per edit.

- [`Serializer.planTree`][ser-tree] keeps each plan's encoded tree in a weak map ([`Kept`][ser-kept]). [`encodeKept`][ser-enc] re-encodes a plan only if its version, name or camera changed. The map is seeded as the file loads.
- [`PlanAPI.recordEdit`][api-rec] bumps the graph's version when an edit changed something. A no-op edit leaves no trace.
- [`PlanAPI.save`][api-save] builds the tree on the game thread and drops it in an `AtomicReference`. A write is queued only if none was pending so the newest save wins. The writer is a single daemon thread ([`WRITER`][api-writer]). A shutdown hook flushes a pending save ([`:225`][api-hook]).
- [`writePending`][api-write] backs up first (once a session and before a save that drops a plan, newest 10 kept). Then it turns the tree into text, writes `plans.dat.new` and moves it over the old file with `ATOMIC_MOVE`.
- The debug copy is gone.

A save now costs the game thread 0.2 ms. Dropping an input into a source drawer is one 78 ms frame. Deleting a drawer is 25 ms.

**The scroll wheel.** [`BoardSession.live`][bs-live] runs each notch at once and touches the graph so it solves while you scroll. [`settleLive`][bs-settle] turns the spin into one undo step and one save after [500 ms][bs-settle-ms] idle. It settles right away before another edit, undo, redo or close. On the card [`commitWheel`][rc-wheel] keeps the wheeled count showing until a newer solve comes back.

## 4. Pasted plans

Commit [893786d](https://github.com/jackwrichards/gtnh-planner-mod/commit/893786d61d8e4f53d25bf02a80a9bd3aaeeb99b8). Found from a player's report on a Cetane-Boosted Diesel setup. 8 of its 28 GregTech cards came in on the wrong machine. One was an HV Steam Compressor running 4x too fast. Its 3 Industrial Farms were left out. Its 10 combustion engines came in sized to 20.8.

**Machines.** The old importer matched the plan's machine label against NEI's catalysts by slug and otherwise kept NEI's first catalyst. That made a Basic Extractor a Steam Extractor. [`GameNodeMaker.pickMachine`][gnm-pick] now goes in this order:

1. A GregTech card takes the first NEI catalyst whose item id is among the machines the plan's recipe map lists for its handler ([`WebCards.handlerItems`][wc-handler], read from `assets/gtnhplanner/machines/handlers.json`).
2. Otherwise it matches by name or family with steam and electric kept apart.
3. If it still landed on a steam machine it switches to the first electric one. Otherwise it keeps NEI's first machine.

[`retier`][gnm-retier] then moves a single block to its family's block at the card's voltage. If the family has no block at that tier it takes the nearest one above, else the highest. The import report says so ([`FfConverter:295`][ffc-report]).

**Steam.** [`GtMachines.Kind`][gt-kind] marks a machine as steam: bronze single blocks, and multiblocks named steam or high pressure. Steam handlers carry no voltage in the machine maths. [`PowerReport.steam`][pr-steam] bills steam at 2 L per EU for single blocks (x2 for high pressure). Multiblocks bill recipe EU × 1.25 × pressure tier × parallels. The card's power row shows L/s and no tier chip.

**Crops, generators and overlaps.** Crop cards are recognised by their category ([`FfPlan.isCrop`][ffp-crop]) and resolved on CropsNH's NEI page ([`CropsNhProvider.crop`][crops]). Generators in a Build plan come over pinned ([`FfConverter.placePower`][ffc-power]). Imported cards are sized differently from the source so they can overlap. [`Unstack`][unstack] moves each overlapping card to the nearest clear 10 px spot on growing rings once the board has solved ([`BoardCanvas:105`][bc-unstack]).

## 5. World overlay

Commits [287dc67](https://github.com/jackwrichards/gtnh-planner-mod/commit/287dc671707621d98eb5c175d39e602e01831b8f), [ebd64f6](https://github.com/jackwrichards/gtnh-planner-mod/commit/ebd64f6ffd33498571e57995ef17705843ac2458), [f36320f](https://github.com/jackwrichards/gtnh-planner-mod/commit/f36320f72b2186f28229fc65eaed3b6ef69660cf), [3010f92](https://github.com/jackwrichards/gtnh-planner-mod/commit/3010f92c4871d9715e7a5fe0dbf93e11d4c50692) and [a50b157](https://github.com/jackwrichards/gtnh-planner-mod/commit/a50b157415d09c69af36d7d021ed430e814c8327).

**Order of placement.** [`PlanOverlay.onOverlay`][po-overlay] places machine labels first, then the cards, then wire labels. Wire labels avoid the labels, the cards, the machine being looked at and the corner panels (minimap, pin list, keys strip and the placing title).

**Wire labels.** [`placeTags`][po-tags] goes nearest wire first. [`choose`][po-choose] tries the label's home spot. Then 17 samples along the visible part of its own wire, nearest first ([`alongWire`][po-along]). A clear spot already held is kept unless a new one is 1.6x nearer. Then 4 spots off the wire with a leader line. If nothing is clear the least overlap wins ([`overlap`][po-overlap]) and must beat the current spot by 20% to move it. Labels glide with `1 − exp(−dt / 70 ms)`.

**Machine labels.** [`MachineLabel.measure`][ml-measure] has four levels of detail (full, no name, tier and count, tier only). It is measured once per card and machine index. A card of several machines shows which one it is (2/4). Focus and Labels are bindings read by key code ([`PlannerKeys:50`][pk]) so a key shared with another binding still works for both.

**Placing.** [`LinkPicker.aim`][lp-aim] ray traces up to 48 blocks then checks the plan's placed boxes through `WorldIndex.along`. The nearest entered face wins so you can build against a ghost like a block. [`WorldMarks.front`][wm-front] lights the front face and draws a ground arrow. It draws twice: faint through walls and solid where depth allows.

**Minimap edge.** The game reports 0 stencil bits. The old circle clip fell back to a depth mask and items undid it, so whole cards leaked past the edge. [`Minimap.clipBegin`][mm-clip] now scissors first and then draws the disc with ModularUI's `Stencil.apply`. The HUD scissor is computed directly. The settings preview takes its scissor from `gluProject` ([`window`][mm-window]).

**Cheaper.** Labels are measured once. Wire label icons come from the icon atlas. Labels and tags have no text shadow.

## 7. Tests and compatibility

- 614 headless JUnit tests in about 40 s with no Minecraft. The machine maths runs against goldens written by the reference implementation (0 mismatches over 42,250 cases). The solver has its goldens plus the path, island, trade rule and stop tests ([`SolveStopTest`][t-stop]).
- Goldens: 32 whole answers in [`solver-corpus/goldens/`][goldens]. `./gradlew test --tests '*SolverGoldenTest*' -Pbench=check` compares. `-PwriteGoldens` records them again.
- `./gradlew compatCheck` resolves every class, method, field and mixin target the mod uses against each GTNH 2.9 build's mod list (beta-1, beta-2, beta-3, RC-1 and RC-2). Every gap must be listed with a reason in `tools/dev/compat/guarded.txt`. One jar runs on all five.
- A build of this code was loaded in the full RC-2 pack. The planner opened and solved imported plans with no errors.

## 8. Known limits

- A newer edit stops AUTO's LPs between models. The drawer relaxation and the integer models behind the Output and Input modes do not check for it.
- On a machine with 2 or 3 cores the solver runs serially (threads = cores − 2).
- Alternatives are capped at 1,024 swaps per solve and 8 options per leftover.
- A machine is "unneeded" when it is unpinned and the trade and flow minimization left it at 0. That is a result of the objective, not a separate graph check.
- Still open in the solver plan: warm re-solves, and a connected plan of a few hundred machines in the corpus to measure what islands cannot help.
