# 0.2.0-beta.2: under the hood

Code links are pinned to [586769d](https://github.com/jackwrichards/gtnh-planner-mod/tree/586769dce948d94172e42d1d7fae37f1df2d8b83). The design, and the contract the game and the website both build against, is [docs/design/cloud-live.md](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/docs/design/cloud-live.md).

## One plan, two editors

A shared plan lives in the player's account on the website. The game and the website edit the same JSON document: the website's own plan format. Nobody sends whole plans around. An edit is a short list of ops on things by id: put, patch (top-level fields), delete, and plan-level fields. [`LiveOps.apply`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/sync/LiveOps.java#L236), [`diff`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/sync/LiveOps.java#L289) and [`invert`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/sync/LiveOps.java#L351) are a Java port of the website's engine. Both run the same 73 test vectors ([`live-vectors.json`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/test/resources/live/live-vectors.json)), so they can't drift apart quietly.

The live service puts every batch in one order. Two writes to the same field: the later one wins. Each client keeps the plan as the service last confirmed it and its own batches still in flight on top ([`LiveState`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/sync/LiveState.java)). Undo applies the recorded inverse of your own batch as a new edit, so it never takes back someone else's. A batch is at most [1000 ops](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/sync/LiveState.java#L206) and 256 KB; a bigger edit splits and still undoes as one.

## The board and the shared plan

[`CloudPlans.read`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/map/CloudPlans.java#L52) and [`write`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/map/CloudPlans.java#L70) turn the board into the website's plan and back. Every card, drawer, wire, note, drawing and group carries the game's own JSON for it under `gtnhplanner`, with a sum of the website's fields. While the website leaves a thing alone it comes back exactly. A thing the website made or changed is built from its fields through the importer, keeping its id ([`PlanIds`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/map/PlanIds.java#L23) turns a website id into a stable UUID) and whatever the website has no place for, like placed machines. Every corpus plan and every website fixture round-trips exactly, and 25 rounds of random edits per plan read back the same.

The website now draws the game's card and drawer sizes, so positions are 1:1 between the two. Posting to the library and importing use the same rule. Groups are the website's boards (pockets), with each member measured from its group's frame ([`PlanRead`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/map/PlanRead.java#L55)). Game plans say they are plan mode ([`Fresh`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/map/Fresh.java#L356)), so the website never converts one. Port rate pins, setting pins and leftover splits are the plan's own fields both ways.

Another player's edit re-reads only what it touched: 1.8 ms on average (2.5 at most) with someone dragging cards the whole time.

## The connection

[`LiveSocket`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/net/LiveSocket.java) is a WebSocket on Minecraft's own netty, so no new library ships and the jar still runs on Java 8. Netty 4.0.10 stalls its TLS 1.3 handshake, so the socket [asks for TLS 1.2](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/net/LiveSocket.java#L285). It also only knows the close codes of RFC 6455 and calls the service's 1012 (restarting) and 1013 (try later) corrupt frames, so the socket [reads the code out of that error](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/net/LiveSocket.java#L480).

Cloud mode starts only once the site's live service [answers](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/net/CloudApi.java#L419). Until then a signed-in player keeps their world's plans.

A batch goes to disk ([`CloudCache`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/store/CloudCache.java)) before it is sent and leaves it once a saved copy holds it. After a crash or a lost connection it goes again; the service knows every batch by its id and applies each once. Cursors and selections go out [at most every 100 ms](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/ui/live/PresenceOut.java#L24); drawing ten other people costs about 0.14 ms a frame.

## Moving your plans

The first time you open the planner in a world signed in, [`Migration`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/cloud/store/Migration.java#L147) backs up the save, then uploads each plan once and writes its account key on the slot before any upload starts. A failed backup stops it. The world's save stays as it was.

## Fixed

- Plans from the library, links and codes lost machine options. A card built from the website's fields came in without its coil or machine options: a Quantium mixer ran as Tin, 388/s against the website's 1.02k. [094ec7c](https://github.com/jackwrichards/gtnh-planner-mod/commit/094ec7c) carries them through `GameNodeMaker` and `PlanExport`.
- Trash drawers were posted as product drawers. [`PlanExport`](https://github.com/jackwrichards/gtnh-planner-mod/blob/586769dce948d94172e42d1d7fae37f1df2d8b83/src/main/java/com/gtnhplanner/library/PlanExport.java#L822) now says trash ([b0b84f4](https://github.com/jackwrichards/gtnh-planner-mod/commit/b0b84f4)).
- NEI 2.8.155 (GTNH 2.9.0-RC-2) and every NEI back to 2.9.0-beta-1 can crash on a search that changes how many items the list shows: [`ItemPanel.updateItemList`](https://github.com/GTNewHorizons/NotEnoughItems/blob/2.8.155-GTNH/src/main/java/codechicken/nei/ItemPanel.java#L77) turns the list back to page 1 on NEI's search thread, which empties `ItemsPanelGrid.gridMask` while the render thread fills it in `getMask`, an NPE. NEI fixed it in 2.8.161 ([NotEnoughItems#1078](https://github.com/GTNewHorizons/NotEnoughItems/pull/1078)), which no 2.9 build ships yet. [`ItemPanelMixin`](https://github.com/jackwrichards/gtnh-planner-mod/blob/09ac4b0d57cfcdd495177765dc2252a17fcf2a2a/src/main/java/com/gtnhplanner/mixins/ItemPanelMixin.java) hands that turn to the render thread, as NEI's fix does.

## Measured

The game against the website in a browser, two accounts, on a local copy of the site and its live service: edits arrive in 27 to 174 ms, the game holds 120 fps while the other player drags (p99 frame 10.9 ms), and cards, drawers, groups and drawings match to the pixel on both sides.
